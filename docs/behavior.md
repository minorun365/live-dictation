# 動作の詳細

## メニューバー

ウィンドウを閉じてもアプリはメニューバーに残り、会議の検知を続けます。アイコンから状態の確認や録音の開始・停止、ウィンドウの再表示ができます。待機中は眠っている絵、録音中はメモを取る絵になります。終了は⌘Qです。

メニューは3つのまとまりに分かれています。

- 録音の操作。待機中は「手動で録音を開始」の下に「Web会議」「対面会議」が並び、選ぶとすぐ日本語で録音を始めます。英語の場合は、その下の「英語で開始」を開いて同じ2つから選びます。ウィンドウで選んでいるモードは変わらないので、次に検知で始まる会議は元のモードのままです。録音中は「録音を停止」と「英語モードに切り替える」に変わります
- 自動で録音する設定（「対面会議を自動で録音」）
- ウィンドウの再表示と終了

## 英語の会議

会議の検知で始まる録音はウィンドウで選んでいるモードになり、初期値は日本語です。英語の会議は、メニューバーから次のどちらかで英語モードにできます。

- 待機中の「英語で開始」は、その録音だけを英語モードで始めます。「Web会議」は相手の声と自分の声を、「対面会議」は同じ部屋の声を英語として文字起こしし、日本語へ訳します。「対面会議」は画面を記録しません。講演を会場で聞くときは「対面会議」を選びます
- 録音中の「英語モードに切り替える」は、日本語で始まってしまった録音を閉じ、続けて英語モードで録音し直します。音声認識の言語は録音の開始時に決まるため、切り替え前の分は別の短いセッションとして保存され、切り替える瞬間の音は欠けることがあります。会議アプリがマイクを離すと止まる動きは、切り替え後の録音にも引き継ぎます。対面モードから切り替えた場合は、画面を記録しない対面の英語モードになります

日本語訳はウィンドウが開いている間だけ動くので、英語モードで録音が始まるときにウィンドウが閉じていれば自動で開きます。

## 話者の分け方

日本語モードでは行頭に「自分：」「相手：」を付けます。声を聞き分けているのではなく、マイクとMacの再生音をそれぞれ別の音声認識にかけている仕組みです。スピーカーで相手の声を鳴らすとマイクにも入り、同じ発言が自分の側にも記録されるため、ヘッドホンの利用をおすすめします。

## 録音中の画面とフタ

録音している間は、画面が省電力で消えないようにします。macOSは画面と音声をひとつの仕組みで取り込むため、画面が消えると録音ごと止まり、マイクの音も入らなくなるからです。録音を終えると元の設定に戻ります。それでも何らかの理由で取り込みが止まった場合は、自動でつなぎ直します。

録音中にヘッドホンをつないだり外したりして音の出力先が変わっても、録音は続きます。切り替わった瞬間の音は欠けることがあります。つなぎ直したことは `events.jsonl` の `meeting_audio_engine_restarted` に記録されます。

録音中にフタを閉じても、録音は終わりません。MacBookはフタを閉じるとマイクがハードウェアで切れるため、閉じている間の音は入りませんが、フタを開けて画面のロックを解除した時点で同じ録音へつなぎ直します。会議室へ移動する間は閉じておき、着いてから開く使い方を想定しています。

マイクの音が入っているかも監視します。取り込みが動いていても、フタを開けた直後に録音を始めたときなど、マイクが無音のまま記録され続けることがあるためです。マイクの音量がほぼ0のまま15秒続くと取り込みを自動でつなぎ直し、直らなければ75秒・255秒の時点でもう一度試します。対面モードでは無音が10秒、Web会議のモードでは3分続くとMacの通知で知らせ、ウィンドウにも表示します。Web会議の待ち時間を長めにしているのは、聞いている間にヘッドセット側で音を切ることがあるためです。記録は `events.jsonl` の `microphone_silent`・`microphone_capture_restarted`・`microphone_recovered` に残ります。

メニューバーから開くメニューの一番上には、いま録音に使われるマイクの名前を出します。これはmacOSの既定の入力で、Bluetoothや外部のマイクならその旨を名前の後ろに添えます。対面モードの録音をMacの内蔵マイク以外で始めたときは、その場で通知します。かばんの中でBluetoothヘッドセットの電源が入り、既定の入力に切り替わってしまうと、会議の声が入らないためです。録音ごとに使ったマイクは `events.jsonl` の `microphone_device` に残ります。

## 自動で録音が始まる条件

会議アプリがマイクを使い始めると録音を開始し、そのアプリがマイクを離してから1分で停止します。

- 対象はZoom、Microsoft Teams、Webex、Slackのハドル、Discord
- ブラウザーのGoogle Meetなどは、マイクと再生の両方を使っているときだけ会議とみなします
- 音声入力アプリやmacOSの音声認識では始まりません
- メニューやウィンドウから自分で始めた録音は、会議アプリの状態では停止しません。止め忘れに備えて3時間で自動停止します

## 対面会議のリマインド

対面会議はどのアプリもマイクを使わないため、会議アプリの検知では始まりません。代わりに、開始5分前に「対面で録音開始」ボタン付きの通知を出します。通知かボタンを押すと、対面モードで録音を始めます。

対面モードで録音している間に Zoom・Meet・Teams などの会議アプリがマイクを使い始めたら、その録音を閉じて Web 会議のモードで録り直し、Macの通知で知らせます。対面の英語モードだった場合は英語の Web 会議モードになります。会議室やブースを予約して Web 会議に出る予定は、予定上は対面に見えるためです。切り替え前の分は別の短いセッションとして残り、切り替え後の録音は会議アプリがマイクを離すと止まります。記録は `events.jsonl` の `mode_switch_requested` に、`reason` を `meeting_app_detected` として残ります。

- 初期値はオフですが、メニューの「対面会議を自動で録音」をオンにすると次の2つが加わります
  - 開始5分前の通知の代わりに、何も録音していなければ対面モードの録音を自動で始め、「録音を止める」ボタン付きの通知を出します。一度始めた会議は、途中で手で止めても始め直しません
  - フタが閉じている間や画面がロックされている間は自動で始めず、フタを開けて画面のロックを解除した時点で始めます。ロック画面のまま始めるとマイクが無音のまま記録されるためです
  - 通知のボタンまたは自動で始めた録音は、終了予定の10分後に止めます。その2分前に「録音を続ける」ボタン付きの予告を出し、押すとその会議の録音を続けます
- 会議の一覧は `~/Library/Application Support/LiveTranslator/InPersonMeetings.json` から読み込みます。アプリはカレンダーに接続しないため、このファイルは下の形式で別のツールから書き出してください。ファイルが無ければ通知は出ません
- 5分前にMacが眠っていた場合は、会議が終わる前に目覚めた時点で通知します
- 直前のWeb会議など別の録音をしている間は通知を出さず、録音が終わってから出します。画面共有中に通知が映るのを避けるためです
- 一覧の更新が30分以上止まると、メニューに「対面会議の予定の取得が止まっています」と表示します

```json
{
  "fetchedAt": "2026-09-28T16:00:00+09:00",
  "meetings": [
    {"id": "abc123", "title": "定例", "start": "2026-09-28T16:30:00+09:00",
     "end": "2026-09-28T17:00:00+09:00", "location": "会議室A"}
  ]
}
```

## 文字起こしの遅れ

録音中は、macOSの省電力でアプリの動きが抑えられないようにしています。音声と認識結果の時間差は `events.jsonl` の `recognition_lag` に約1分ごとに記録され、60秒以上遅れると溜まった分の確定を認識エンジンへ促します。このとき、文の途中で確定して切れることがあります。

## 保存されるもの

`~/Library/Application Support/LiveTranslator/Sessions/` の下に、セッションごとのフォルダを作ります。

- 録音音声（日本語モードは自分と相手を別ファイルに分けます）
- Markdownの文字起こしと要約
- 録音中の画面を1秒ごとに撮った `screenshots/`（会議のウィンドウが見つかればそのウィンドウだけ、見つからない間は全ディスプレイを並べた1枚）
- ディスプレイ全体を記録した `screens/display-1/`、`screens/display-2/` …（下の「ディスプレイ全体の記録」）

`screenshots/timeline.md` には画面が変化した時点をまとめてあり、Claude Codeなどからそのまま読み込めます。外部サーバーへ送信するコードは含みません。録音対象者や主催者の許可を得たうえで使用してください。

## ディスプレイ全体の記録

会議のウィンドウの撮影とは別に、録音中は各ディスプレイの全体も記録します。別窓のチャット、共有している自分の資料、手元で開いたほかのアプリなど、会議のウィンドウの外にあったものを後から確かめるためです。対面モードでは、どちらの画面も記録しません。

- ディスプレイごとに長辺1,920pxの画像として分け、`screens/display-N/` に保存します。番号は録音中にそのディスプレイを最初に見つけた順です
- 3秒ごとに画面を確認し、前回の画像から変化があったときだけ保存します。変化が無くても60秒に1枚は残します
- 1Password、パスワード（macOS）、キーチェーンアクセス、Bitwarden、Dashlane、LastPass、Keeper、Enpass、KeePassXC、Proton Pass、macOSのパスワード・Touch IDの入力画面は、写らないようにウィンドウを取り除いてから撮影します。会議のウィンドウが見つからない間に撮る `screenshots/` でも同じ扱いです。ブラウザー拡張として動くパスワード管理の小窓はブラウザーのウィンドウの一部なので、取り除けません
- 記録されるのは前面に見えている部分だけで、裏に隠れたウィンドウや次の撮影までに流れたチャットは写りません
- 画像はこのMacのセッションフォルダにだけ置き、外へは送りません。どのディスプレイを撮ったかや、除外したアプリが起動していたかは `events.jsonl` の `full_screen_capture_displays` に残ります
